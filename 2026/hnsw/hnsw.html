1. The Multi-Layer Skip-Graph

Vector databases serve millions of queries by matching high-dimensional embeddings in microseconds. Traditional exact search requires a linear scan across every vector. This creates a bottleneck at scale. HNSW structures the vector space as a vertically stacked graph index. This index achieves logarithmic search complexity.

The core architecture is inspired by the skip-list. The skip-list speeds up search in sorted lists by maintaining sparse, high-level shortcuts. HNSW adapts this mechanism to multi-dimensional graphs.

Note: Higher layers feature sparse, long-range connection expressways. Lower layers resolve localized coordinate neighborhoods. The bottom layer (Layer 0) holds all data vectors.

Each node that exists on a higher layer is duplicated on all layers below it. These duplicates are connected vertically. The searcher hops across the sparse top layers to zoom near the target before dropping down to dense layers.

2. Search Routing via Greedy Walks

HNSW searches the stack using a greedy routing walk. At the active node, the searcher calculates the distance between the query point and all connected neighbors. The searcher hops only to neighbors that are strictly closer to the query than the active node. When no closer neighbor is found, the searcher reaches a local minimum. The searcher then drops vertically to the layer below and resumes the greedy walk.

Step-by-Step Traversal Walkthrough

Let us trace a routing path. The target query point is at coordinates [3.0, -2.0].

Layer 2: Sparse Expressway

The walk begins at Node A. The searcher evaluates Node D. Since Node D is closer to the query, the searcher hops to D. From Node D, the searcher evaluates Node E. The distance to Node E is shorter, so the searcher hops to E. At Node E, all neighbors are farther. The searcher stops at E.

Layer 2 Cost: 2 hops.

Layer 1: Coarse Street Grid

The searcher drops vertically from Node E on Layer 2 to Node E on Layer 1. The searcher probes the local neighbors: D, X, and H. Node H is closest, so the searcher hops to H. From H, the searcher hops to I. From I, the searcher hops to K. At K, all neighbors are farther from the query. The searcher stops at K.

Layer 1 Cost: 3 hops.

Layer 0: Dense Base Layer

The searcher drops from K on Layer 1 to K on Layer 0. The base layer contains all data points. The searcher probes the dense local connections. Node R is closer, so the searcher hops to R. From R, the searcher hops to P. At Node P, no neighbors are closer. The searcher declares Node P the global nearest neighbor.

Layer 0 Cost: 2 hops. Total Walk Cost: 7 hops.

This hierarchical approach avoids flat scans. In a database of 1,000,000 vectors, exact search performs 1,000,000 distance evaluations. HNSW finds the nearest neighbor in exactly 7 hops.

3. Graph Construction & Heuristics

Building an HNSW graph requires establishing connections during node insertion. The graph must remain sparse and navigable.

Phase 1: Layer Selection (Exponential Decay)

When a new node enters the index, the algorithm assigns it a maximum layer. To keep the expressways sparse, the algorithm uses exponential decay. The probability of a node existing on a higher layer drops rapidly.

The maximum layer is calculated as: \[L_{\max} = \left\lfloor -\ln(u) \cdot m_L \right\rfloor\] Where \(u\) is a uniform random decimal between 0 and 1, and \(m_L\) controls the decay scale.

How are these values calculated?

The normalization scale is set to \(m_L = \frac{1}{\ln(M)}\). This guarantees that the overlap between subsequent layers behaves as a skip-list with an active step size of \(M\). Drawing a random decimal \(u\) from a uniform distribution shifts the layer assignment exponentially.

import math
import random

M = 16
m_L = 1.0 / math.log(M)
u = random.uniform(0.0, 1.0)
l_max = math.floor(-math.log(u) * m_L)

Disclaimer: Real-world probability shares may vary slightly due to floating-point rounding.

Phase 2: Routing Downward

After selecting the maximum layer, the node must be inserted. The algorithm begins a greedy walk from the top entry point of the index. It travels downward through the layers, finding the local minimum at each layer. Once the walk reaches the node's maximum layer, it shifts from routing to connection wiring.

Phase 3: The Diversity Heuristic

When connecting the new node to neighbors, a naive approach would connect to the absolute closest points. However, this creates highly clustered graphs. If nearby nodes cluster in a single direction, future searchers approaching from other directions cannot traverse the graph.

HNSW avoids this clustering by using a diversity heuristic. The algorithm evaluates candidate nodes sequentially. A candidate is accepted only if it is closer to the new node than it is to any already connected neighbor. This ensures edges extend in diverse directions, forming global shortcuts.

Phase 4: Base Layer Connection & Pruning

Once connections are established, HNSW checks each connected node against a maximum connection budget. If any node exceeds the connection budget, the algorithm executes the diversity heuristic specifically on that node's neighbors. It prunes redundant connections. This keeps memory consumption bounded.

4. Tuning Hyperparameters in Production

HNSW is highly tunable. Three parameters control the balance between retrieval speed, memory consumption, and search recall.

The Vector Search Trade-off Triangle

Vector indices operate within a physical trade-off triangle. You can optimize for speed or accuracy, but higher settings increase resource footprints.

  • Recall Accuracy: The percentage of queries returning true nearest neighbors.
  • Search Latency: The volume of queries resolved per second.
  • Memory & Build Time: The RAM footprint of the index.

How are these values calculated?

Metrics are calculated using an empirical scaling model for a dataset of 1,000,000 vectors:

  • Recall: Estimated as \(1 - e^{-c_1 \cdot ef_{\text{search}} / M}\). Higher active search sizes increase accuracy.
  • Latency: Calculated as \(c_2 \cdot ef_{\text{search}} \cdot \log(N) / M\) milliseconds.
  • Memory: Bounded directly by \(N \cdot M \cdot d\) bytes, representing the graph skeletal coordinate array.
  • Build Speed: Inversely proportional to \(ef_{\text{construction}}\), as larger queues require additional distance evaluations.

Disclaimer: Real-world latency depends on hardware specifications, core count, and vector dimension sizes.

5. Conclusion

HNSW provides extreme query performance by combining structured multi-layer graph skip-lists with localized coordinate routing. By matching decaying densities with connection heuristics, the graph prevents clustering and preserves paths. Tuning the parameters dynamically optimizes HNSW across diverse enterprise search applications.
